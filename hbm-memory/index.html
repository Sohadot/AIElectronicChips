HBM Memory

HBM4 doubles the memory interface to 2,048 bits and moves the stack's base die onto logic processes. That second change ties the memory layer to advanced-logic fabrication.

This reference explains how High Bandwidth Memory works and what changes from HBM3E to HBM4 and HBM4E. It sets JEDEC's announcement of the standard against what suppliers and accelerator vendors have disclosed, and records where those disclosures conflict or stop.

00

Reference summary

Definition. High Bandwidth Memory (HBM) is DRAM built as a vertical stack: several DRAM core dies sit on a base die and connect to it through through-silicon vias (TSVs). The stack is then placed inside the same package as a processor, beside it. ASK hynix describes HBM as "made by stacking a core DRAM die on top of a base die that features TSV". [2]

Why it is a dependency layer. An accelerator can only compute as fast as data reaches it. HBM supplies that data over a very wide, short connection, and it does so only after successful integration in an advanced package. A memory stack is therefore not usable on its own: it depends on DRAM fabrication, on logic fabrication (for HBM4 base dies), and on packaging capacity.

What changed with HBM4. HBM4 brings three changes: twice the interface width, more channels, and taller permitted stacks. For the suppliers that disclose it, the base die now comes from a logic process instead of a memory process. The sections below separate each claim by evidence class.

Boundary. This page reports what standards bodies and companies have published. It does not establish availability, allocation, yields, production capacity, qualification status or relative supplier position. Supplier efficiency figures use different baselines and cannot be compared with each other.

01

How an HBM stack works

Conventional DRAM interfaces run a narrow bus fast. HBM takes the other route: an extremely wide bus at moderate per-pin speed. That trade only works because the memory sits beside the processor in the same package, where thousands of short connections are practical, rather than across a circuit board.

  • Core dies hold the DRAM arrays. Capacity grows with layer count and per-die density. SJEDEC's HBM4 announcement lists 4-, 8-, 12- and 16-high DRAM stacks of 24 Gb or 32 Gb dies, and a 64GB cube (32 Gb, 16-high). [1]
  • TSVs carry signals and power vertically through each core die to the base die. This removes the long wires a board-mounted memory would need.
  • The base die carries the interface and control logic that faces the processor. With HBM4, suppliers that disclose it make this die on a logic process (see section 04).
  • Channels. SJEDEC's announcement states that HBM4 has 32 independent channels per stack, each with two pseudo-channels, up from 16 channels in HBM3. [1] More independent channels let the controller keep more transfers in flight at once.

03

Bandwidth arithmetic C

Per-stack peak bandwidth is the interface width times the per-pin rate, divided by eight bits per byte. The table applies this to a 2,048-bit interface and sets the result beside the disclosed figures.

What this shows. Every disclosed HBM4 and HBM4E bandwidth figure is consistent with a 2,048-bit interface at the stated pin rate. That includes Samsung's HBM4E figures, whose release does not give an I/O count. Arithmetic consistency is not proof that HBM4E keeps the 2,048-bit width; it means the disclosures do not contradict it. The same arithmetic explains the "doubling" language: widening from 1,024 to 2,048 bits doubles bandwidth at an unchanged pin rate.

Two cross-checks. Samsung's HBM4 maximum of 3.3 TB/s matches its 13 Gb/s enhanced rate, not its 11.7 Gb/s consistent rate. For HBM3E, 1,024 bits at Samsung's stated 9.6 Gb/s gives 1.23 TB/s. That agrees with Samsung's "2.7x" multiple (3.3 ÷ 2.7 ≈ 1.22) and with the 1.2 TB/s Micron cites. [7][9]

04

The base die moves to logic

The base die is the structural change in HBM4 with the largest dependency consequences, and the least discussed.

  • ASK hynix stated in April 2024 that it "has used a proprietary technology to make base dies up to HBM3E" and "plans to adopt TSMC’s advanced logic process for HBM4’s base die". [2]
  • ATSMC listed "N12 and N3 logic base die for HBM4" among its offerings in April 2025. It did not name the customers or products using each node. [12]
  • ASamsung states it "adopted the most advanced nodes like the 1c DRAM and 4nm logic process for HBM4". [9] That release does not name the unit that makes the die. Samsung's HBM4E release attributes the 4nm logic base die to Samsung Foundry. [11]
  • AMicron's FY2026 Form 10-K states its HBM4 uses advanced CMOS technology "on the base logic die and DRAM core dies, which are designed and manufactured in-house". [18] It does not state the base die's process node, and Micron's product releases do not mention the base die.

Dependency implication C

For suppliers whose HBM4 base die comes from a logic process, HBM4 output depends on two separate fabrication flows: DRAM wafers for the core dies and logic wafers for the base die. Package integration then adds a third dependency. The three suppliers reviewed here describe three different arrangements. SK hynix's disclosed plan relies on an external foundry. Samsung's relies on its own foundry business, per its HBM4E release. Micron reports designing and manufacturing the base logic die in-house, without naming its process. So the base-die dependency is not uniform across the industry: it is external, intra-company or internal depending on the supplier. This analysis assumes SK hynix carried its 2024 plan into production, which neither its later releases nor the portion of its 2026 prospectus reviewed here restate. It makes no claim about capacity, allocation or constraint severity.

AThe same SK hynix announcement refers to "customized HBM that meets a wide range of customer demand for performance and power efficiency". [2] AIts July 2026 prospectus defines custom HBM as "an HBM product that integrates certain functions of GPUs and ASICs into the HBM base die". [20] CWhere custom HBM is used, it ties a memory supplier, its base-die source and one accelerator design more closely together.

05

Stacking and packaging

Inside the stack

  • ASK hynix uses Advanced MR-MUF (mass reflow molded underfill) in HBM4 and says it "helps prevent chip warpage" while improving heat dissipation. [3][4]
  • AMicron reports shipping 48GB 16-high HBM4 samples, a 33% capacity increase per HBM placement over 36GB 12-high. Its stacking method is not disclosed. [8]
  • ASamsung presents hybrid copper bonding as a method that "will enable next-generation HBM to achieve 16 or more layers" with heat resistance more than 20% below thermal compression bonding. It is not stated as used in HBM4 or HBM4E. [10]

Into the package

  • ATSMC says it "continues to advance its Chip on Wafer on Substrate (CoWoS®) technology" for AI's need for logic and HBM. It plans 9.5-reticle CoWoS in volume production in 2027, "enabling integration of 12 HBM stacks or more in a package". The 2027 date is a plan. [12]
  • ASK hynix's 2024 MOU announcement aimed to "optimize the integration of SK hynix’s HBM and TSMC’s CoWoS" technology. [2]
  • UThe reviewed sources do not identify per-product interposer or bridge type, substrate suppliers, assembly sites, or how stacks are tested before integration. Those dependencies are real, but this release cannot yet attribute them.

CStack count per package and stack height compound. Twelve 16-high stacks would put 192 core dies, plus base dies, into one package. Package-level yield, warpage and thermal limits therefore sit alongside DRAM yield as constraints. That is a structural point and does not claim any particular yield.

08

Accelerator integration

ANVIDIA's Rubin platform article (2026-01-05) lists "Aggregate bandwidth of up to 22 TB/s". [17] Its GPU architecture article (2026-07-21) states that Rubin "integrates up to 288 GB of HBM4 memory, driven by dedicated HBM controllers and 12-Hi stacks", with "up to 22 TB/s of peak bandwidth". [14]

ANVIDIA's later technical article (2026-11-05) states: "From GB300 to NVIDIA Rubin, capacity held at 288 GB while bandwidth rose to 19.2 TB/s." It gives no qualifier and does not mention 22 TB/s. [15]

UConflict. NVIDIA's dated articles move from "up to 22 TB/s" (January and July 2026) to an unqualified 19.2 TB/s (November 2026), for the same 288 GB Rubin GPU. Its current, undated product pages still disagree: 19.2 TB/s per GPU (1,400 TB/s per rack) on the Vera Rubin NVL72 page, and 22 TB/s on the HGX page. [16] No page labels either figure preliminary, projected or subject to change, and none explains the difference. What the record shows is that the higher figure is the one stated as "up to" or "peak", and the lower one is the more recent. This reference does not infer why. A later revision, a configuration difference and a peak-versus-rated distinction all remain possible.

What the figures imply C

If 288 GB comes from 36GB 12-high stacks, as SK hynix and Micron disclose for 12-high HBM4, Rubin carries eight stacks. NVIDIA does not state the count. At 2,048 bits per stack:

  • 22 TB/s across eight stacks is about 2.75 TB/s per stack, or about 10.7 Gb/s per pin.
  • 19.2 TB/s (the 2026-11-05 figure) across eight stacks is about 2.4 TB/s per stack, or about 9.4 Gb/s per pin.

Either way, the platform depends on HBM4 speed grades above the 8 Gb/s that JEDEC announced. That is the practical meaning of the supplier pin-rate disclosures: the platform needs above-baseline parts that suppliers must qualify. Assumptions: equal 36GB stacks, a 2,048-bit interface per stack, and all stacks at the same rate.

09

Substitution: technically indicated, commercially unverified

AMicron says its HBM4 is "designed for NVIDIA Vera Rubin" [8], and Samsung says the same of its HBM4 [10]. SK hynix's reviewed releases name no platform.

CThe platform is therefore designed to accept HBM4 from more than one supplier. That establishes technical multi-sourcing intent only. No reviewed source states whether supply can in practice shift between suppliers, or at what qualification status, speed grade, package variant or volume. "Designed for" is an interoperability target, not a disclosed qualification.

UA second route, a reduced-pin-count HBM4 variant, has been reported but is not used here as evidence. Its JEDEC source could not be retrieved.

10

Unresolved questions

These are material questions the current evidence cannot answer reliably. They are recorded here, not filled with general industry commentary.

  1. JEDEC standard text. The announcement figures marked S have been read in JEDEC's Business Wire release, via a syndicated copy. The normative JESD270-4 and JESD270-4A documents have not been reviewed, so nothing here states what the standard itself requires.
  2. HBM4E standard. No reviewed source cites a published JEDEC HBM4E document.
  3. Micron base-die node. Micron reports in-house design and manufacture but does not state the process node.
  4. Samsung HBM4 base-die manufacturer. Samsung's HBM4 release names a 4nm logic process but not the unit that makes it.
  5. SK hynix base die in production. The 2024 TSMC plan is not restated in later reviewed releases.
  6. Capacity, yield and allocation by supplier. No primary source quantifies them, and this project does not estimate them.
  7. Qualification. Which suppliers' parts are qualified for which platforms, at which speed grades.
  8. Rubin bandwidth. "Up to 22 TB/s" (2026-01-05, 2026-07-21) versus an unqualified 19.2 TB/s (2026-11-05), with NVIDIA's current product pages still split (section 08).
  9. 16-high thermal limits and whether hybrid bonding becomes necessary.
  10. Interposer, substrate and assembly dependencies for specific HBM4 packages.
  11. Pre-integration test flows (known-good-stack testing) and who performs them.
  12. Reduced-pin-count HBM4 variants, including their status and scope.
