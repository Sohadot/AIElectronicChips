Industrial Evidence Request & Research Workbench

The documents a researcher would need to answer three questions about HBM4 integration, accelerator bandwidth and AI rack deployment, and what each would still leave open.

Every requirement is traced to the release findings, registered sources and conflict-register entries behind it. Where reviewed sources are silent, the requirement is marked as this project's recommendation.

Not an assessmentThe workbench prepares evidence requests. It does not state that any product, supplier or site meets a requirement, and it produces no readiness, qualification, compliance or comparative result.

Privacy: statuses and notes stay in this browser tab. They are not sent, stored or added to the address, and reloading the page clears them.

01

How to use the workbench

Each workflow starts from one research question and lists the documents a researcher would need to answer it, 41 requirements in all. For every requirement the catalog says whether reviewed public sources already publish the information, which release findings and registered sources it rests on, which entries in the conflict register affect it, and what a received document would still not establish without expert review.

BoundaryEvidence-request preparation, not an assessment. A requirement names documents a researcher would need; it does not state that those documents exist, that any product meets the requirement, or that any dependency is approved. User-recorded statuses stay in the browser and are never validation: a received document has not been reviewed, authenticated or found sufficient. Compiled 2026-11-11; scientific review pending. Machine-readable model: industrial-evidence-requests.json.

02

Workflow A: HBM4 integration evidence request

Research question. What documentary evidence would be required to substantiate the integration and qualification of named HBM4 memory in a specific AI accelerator package?

Objective. Collect the documents that separate an interface standard and supplier announcements from product-specific integration and qualification. Related pathway: Pathway A on the Sovereignty Stack.

  1. A1

    HBM4 interface standard and revision

    PpPublic availability: Partially published

    Specification · Memory · Source-derived

    Document to request. The normative JEDEC JESD270-4 text (and any revision, such as JESD270-4A) that the memory and the accelerator's memory controller are designed to

    Why it matters. The interface defines width, channels and signalling. JEDEC's public announcement is not the normative text, and the revision in use decides which speed bins and timing apply.

    Reference section →

    Evidence trace and limits
    Technical scope
    Per HBM4 stack interface
    Release findings
    f-std-interface (aec-hbm4-evidence-release-001), f-std-channels (aec-hbm4-evidence-release-001), f-std-compat (aec-hbm4-evidence-release-001)
    Registered sources
    • jedec-jesd270-4-hbm4-standard-2025: JEDEC Solid State Technology Association, “JEDEC and Industry Leaders Collaborate to Release JESD270-4 HBM4 Standard: Advancing Bandwidth, Efficiency, and Capacity for AI and HPC”, 2025-04-16. Original source
    Open questions
    • u-jedec-text: What do the normative JESD270-4 and JESD270-4A documents specify beyond the announcement, including timing, any speed bins above 8 Gb/s and the revision-A changes?
    Consider on receipt
    • Names the exact document number and revision
    • States the speed bins and voltage options used
    Limitations
    • The normative text is distributed by JEDEC and was not reviewed by this project
    After expert review
    Could support a bounded statement about: Which interface parameters the integration must meet
    Not established without review
    That any named part or package conforms to the standard

    That the named part is qualified in the accelerator

Workflow B: Accelerator bandwidth comparison evidence request

Research question. What evidence is required before comparing memory and interconnect performance between two accelerator systems?

Objective. Collect the documents that fix each figure's unit, direction, scope, basis and measurement before any comparison is drawn. Related pathway: Pathway B on the Sovereignty Stack.

  1. B1

    System identification and generation

    PPublic availability: Published

    Specification · Design · Source-derived

    Document to request. The exact product, SKU, generation and configuration for each system being compared

    Why it matters. Vendors publish different figures for different products (for example Rubin on HGX and on Vera Rubin NVL72). A comparison needs the configuration fixed first.

    Reference section →

    Evidence trace and limits
    Technical scope
